1．目标、范围与实施状态

建立独立的 UI 布局与视觉资产模板库：用户提供来源项目目录，工具提取结构和视觉证据，正式 PostgreSQL 保存权威版本，Qdrant 建立可重建检索索引，Agent 选择模板、应用目标风格，再由 UnityCLI 创建与验证预制。

本机数据作为验证样本保留；正式库重新设计，不直接把本机试验表结构视为正式标准。不清空本机数据，不启动 Track 流程，不因本文创建数据库、迁移或批量生成资产。

本纲要是开发设计基线 v1.1，日期 2026-10-13；不是已实现能力清单。数据库物理 DDL、JSON Schema、命令参数与模型选型需要在实施阶段验证。

项目当前证据／边界
本机验证会话记录中 SV 扫描 2,833 个预制，成功入库 2,806 个，27 个未成功；已有离线提取和部分重建样例。这些是历史验证结果，本次未重新统计。
服务器会话中已验证 PostgreSQL 16 与 Docker Qdrant 1.19.2 可运行；Qdrant 当时为空且仅本机监听。本次文档编写未重新检查服务器。
正式库与索引本纲要中的独立库、统一资源版本、风格分析及索引同步均为待实施设计，不声称已完成。
与旧纲要关系旧《GameAI-UI布局与视觉表现模板库开发纲要》保留为背景与原型记录；正式库职责、引用格式和版本规则以本文为新基线。

2．模块职责与完整链路

模块职责禁止混入
GameCLI 离线提取器（C#/.NET 8）扫描外部目录、解析 Unity 序列化资产与 .meta、建立 GUID 映射、输出版本化数据包不得要求每个源工程安装 UnityCLI；不得修改来源工程
UnityCLI（当前 Unity 宿主）通过 Unity API 提取可验证信息、重建支持范围内的资产、渲染预览和验证不保存数据库密码，不直接连接 PostgreSQL/Qdrant，不破坏用户场景
视觉分析适配层依据真实截图和切图生成风格观察、置信度及证据引用不得从文件名臆造材质和表现；不得将推断写成提取事实
GameAI.Server 导入服务（Node.js）契约校验、去重、事务入库、版本与权限、索引待办不以本地文件或 Qdrant 代替权威数据
索引工作进程生成摘要与向量、重试、同步及重建 Qdrant 索引不决定资产是否完整或允许生产
Agent 与生图适配选择模板、应用项目目标风格、形成生成参数并调用生图；记录结果不绕过校验，不承诺生成图片天然符合九宫格或每次完全相同
来源目录（只读） → 离线提取 → 数据包校验 → PostgreSQL 发布版本
                                    ↓                 ↓
                             Unity 重建验证       索引待办 → Qdrant
需求 → 语义召回 + 结构筛选 → 读取完整模板 → 白模 → 生图与装配 → 验证与交付

原工程无法加载、自定义代码缺失或版本不兼容时，允许保留参考数据，但必须标明局限；不能称为完整等价还原。当前 Unity 项目不能替代所有源项目的运行环境。

3．正式 PostgreSQL 数据模型

建议独立数据库 gameai_asset_library，与 Track 数据库分开。以下表名为逻辑设计，实施阶段形成迁移脚本与索引。

Schema / 表核心内容与约束
catalog.sources来源 ID、项目标识、Unity/包/管线版本、目录快照、使用权限；路径只是来源信息，不是全局主键
catalog.templates / template_versions稳定 UUID；来源项目 + 源 GUID 唯一身份；不可变版本保存规范化 JSONB、schema_version、content_hash、提取器版本
catalog.categories / template_categories / tags / template_tags功能分类多对多、结构标签；分类关联记录人工确认或自动推断、方法版本
catalog.template_dependencies所属版本、依赖模板版本、实例节点 ID、实例覆盖；循环依赖阻止可重建发布并给出路径
catalog.template_bindings所属版本、节点、组件、属性槽位、资源版本或内部组件目标；从契约投影生成
assets.resources / resource_versions统一资源身份与不可变版本，kind 区分 texture/font/animation/animator/effect/material/shader-intent；参数 JSONB 使用分类型 schema
assets.blobs / resource_blob_bindingsSHA-256、字节数、MIME、bytea；版本到多个文件的用途映射，支持字体图集等复合资源
assets.resource_dependencies资源版本 → 资源版本，含用途和槽位；合法互相引用作为依赖图处理，不强行要求所有资源为 DAG
assets.visual_profiles / visual_profile_versions / visual_profile_bindings版本化源风格与目标风格、证据、置信度、审核状态；窗口和控件局部覆盖
assets.generation_specs / generation_runs / generation_outputs生成约束、输入模板/风格版本、实际提示词、参考图、工具或模型标识、输出资源与检查结果
ingestion.import_batches / import_items来源快照、幂等键、文件状态、错误码、检查点、提取诊断；支持部分成功的明确报告
validation.runs / findings / previews模板版本、验证器与环境版本、测试结果；预览关联 blob 与采集条件
search.documents / embedding_profiles / index_jobs摘要及哈希、生成方法、模型/维度/距离度量、索引代次、待办与重试；模型先确定后建集合

3.1 物理约束

  • 身份、版本使用 UUID；同名 UI 可以来自不同项目，路径变更不产生新的逻辑身份。
  • 内容相同的重复导入不新增版本；唯一约束与事务处理并发，不能仅靠先查后写。
  • 哈希按规范化 JSON 计算，包含会影响重建的引用版本，不包含导入时间、预览和审核状态；数组中节点同级顺序与动画关键帧顺序不得随意排序。
  • JSON 与关联表同一事务生成；JSON 为结构依据，关联表用于校验、查询和反向追踪，禁止两份人工修改。
  • 文件 bytea 按哈希去重；列表检索不查询二进制字段，导入限制单文件与批次大小，避免一次载入全部资源。
  • 来源缺失、删除采用失效或墓碑记录；仍被版本引用的文件不得直接物理删除。垃圾回收必须检查引用并有保留期。

第一版特效和动画共用资源表与版本机制，分别提供类型视图与严格参数契约；不重复建设独立的身份、版本和依赖系统。为来源 GUID、版本哈希、外键及高频筛选建立索引；JSONB GIN 只针对已确认查询场景。

4．导出包与三个统一契约

export/
  manifest.json
  templates/<local-id>.json
  resources/<local-id>.json
  blobs/<sha256>
  previews/<sha256>.png
  diagnostics.json

三份契约为：模板契约（布局、层级、组件与绑定）、资源契约（文件及视觉参数）、证据与验证契约（来源、诊断、预览与验证）。数据包中的本地 ID 经导入映射为库内 UUID，离线提取不需要访问数据库。

manifest 必须包含格式版本、提取器版本、来源快照、每文件相对路径/大小/哈希、条目与引用清单。不允许越界路径、符号链接绕过根目录、未登记文件或伪造哈希。非有限数值不可静默改成零，应记录不可表达值并按契约阻止重建。

4.1 模板顶层结构

{
  "schemaVersion": "ui-template/2 (proposed)",
  "metadata": {
    "templateId": "本地身份或UUID",
    "versionId": "入库后版本UUID",
    "name": "UILogin",
    "source": {}
  },
  "references": {
    "prefabs": [],
    "resources": []
  },
  "hierarchy": {
    "rootNodeId": "loginRoot",
    "nodes": []
  },
  "bindings": [],
  "behaviorSlots": [],
  "environment": {},
  "diagnostics": {}
}

统一使用 references.prefabs 与 references.resources；动画、特效在 resources 中按 kind 区分，不再同时维护 animations/effects 两套引用列表。示例中的 proposed 是规划标识，正式发布时使用已注册 schema 字符串。

4.2 引用类型

外部资源引用固定到 resourceVersionId；嵌套预制固定到 templateVersionId，并指定挂载节点及覆盖。内部组件引用使用 nodeId + componentId，不使用易变显示名称。动画和特效可复用槽位通过 bindings 映射到实例节点。

质量结果与检索摘要独立存储，更新验证或分类不改变原始布局版本。生成目标要求也不写回源模板。

5．结构与组件提取规范

领域必须保留
节点稳定 ID、标准英文名称、父节点、siblingIndex、activeSelf、RectTransform 锚点/轴心/偏移/旋转/缩放
适配Canvas 模式、CanvasScaler 参数、参考分辨率、安全区策略及证据来源；场景上下文未知时记录 unknown
动态布局LayoutGroup、ContentSizeFitter、LayoutElement、优先级、间距、内边距、内容溢出与裁剪
滚动列表ScrollRect → Viewport/RectMask2D → Content → 单元；方向、惯性、边界、滚动条绑定
交互组件Button.targetGraphic、Selectable 导航、状态颜色/图片/动画触发器、ToggleGroup 等内部引用
文本原始内容或动态槽位、字体、字号、对齐、换行/溢出、TMP 字体资产和回退依赖
嵌套与变体基础预制版本、实例标识、属性覆盖、节点或组件增删；不可解析变体明确失败或参考状态

支持原生 Unity、UGUI 与明确适配的官方包组件；自定义脚本不复制、不执行、不保留可调用的原项目回调。组件白名单和版本适配表必须显式维护，未知 MonoBehaviour 不能按名称猜测为标准组件。

生成的新预制采用 UI + 功能英文名，例如 UILogin.prefab；子节点使用 LoginBackground、Version、LoginButton 等名称。源资产原名称仍作为来源元数据保留；若规范化改名，必须同步引用且保留映射。

按钮用途、列表数据槽位、动态文本和打开关闭约定归入 behaviorSlots。用户意图或推断的触发规则不能冒充原始脚本逻辑；实际业务仍由目标项目实现。

6．图片、风格与生图生产

信息规范
图片事实原文件、尺寸、实际透明像素、透明通道、Sprite 子图 rect、pivot、PPU、border（左下右上）、图集旋转/裁边、纹理导入信息
显示事实Image 模式、节点颜色乘法、材质、Mask、绘制顺序、射线接收、按钮实际状态实现
源风格色板、材质观感、轮廓、描边、装饰密度、光影、字体特征；引用实际证据并记录分析方法/置信度/人工确认
目标风格项目单独配置且版本化；不可覆盖源风格；不是通用 Art 技能中的固定游戏风格
生成约束像素尺寸、透明区域、九宫格边距、拉伸区、文字留白、状态要求和控件用途；数值来自事实或明确目标约定
生成追溯模板/节点/资源/风格版本、实际提示词、参考图哈希、工具标识、时间、输出哈希、校验结果；不保存令牌

不得只保存“某某游戏风格”这一句话。不得伪造正常/按下/禁用图片：原按钮若使用 ColorTint，应记录 ColorTint；目标生产需要新状态时另建生成要求。文字原则上由独立文本节点绘制，既有源图中的烘焙文字如实记录。

生图结果须检查实际尺寸、透明边缘、角部完整性、中心拉伸和状态一致性；按目标窗口装配验证。记录提示词可追溯，但不承诺图像生成逐像素可复现。原图、生成图和原始参数均应各有身份与版本。

7．动画、特效与 Shader 契约

资源参数与依赖
AnimationClip帧率、时长、循环/Wrap、浮点与对象引用轨道；时间/值/入出切线/权重/插值；目标组件属性槽位
Animator控制器、参数、层、状态、混合树、过渡条件/时长/退出时间、Clip 引用；StateMachineBehaviour 作为排除项诊断
动画事件保存非执行性的事件存在证据和意图；不得将原自定义函数回调直接恢复执行
ParticleSystem主模块、发射和 Burst、形状、生命周期、速度、颜色/尺寸/旋转随时间曲线、纹理动画、拖尾、渲染、随机种子策略
特效空间与挂载本地/世界模拟空间、父节点、局部变换、排序、遮罩/裁剪要求、停止/清理约定、子发射器和子特效引用
材质纹理槽位、颜色/数值参数、渲染状态与 shader-intent 引用；不依赖原 Shader 可编译
Shader 实现描述输入纹理用途、UV 操作、时间驱动、混合/深度/剔除/队列、遮罩要求、表现目标及可接受近似；分离事实与分析

未支持的模块、曲线或自定义行为必须产生诊断，不静默丢失。无效资产不可标记完整还原；提取成功、结构验证通过、视觉近似和原效果等价是不同结论。

资源图可能存在控制器、材质或特效之间的互引，应两阶段分配 ID 再连接引用；预制递归嵌套等不合法循环另行拒绝。单纯对所有资源拓扑排序无法处理合法互引。

9．提取、校验、入库与恢复

  1. 扫描来源快照，记录文件清单、GUID、哈希、版本和使用权限；源目录只读。
  2. 提取节点与资源图，识别嵌套、内部引用、自定义脚本和未知字段；逐文件记录结果。
  3. 导出数据包并校验 JSON Schema、文件哈希、节点唯一性、父子关系、引用类型、参数范围和依赖闭合。
  4. 将二进制按哈希暂存或去重，解析本地 ID 到稳定身份与版本；原文件与规范化参数哈希分开。
  5. 以一个根模板及其依赖闭包为发布单位，在事务中写入版本、关联和索引待办。共享依赖按唯一约束复用。
  6. 失败条目保留诊断；缺失依赖的模板可以保存为不可重建参考件，但不得混入完整模板结果；批次报告明确成功/参考/失败。
  7. 重复执行依据快照、幂等键和检查点恢复；数据库提交后响应丢失时查询结果，不能无条件再建版本。

不跨 PostgreSQL 与 Qdrant 假装一个原子事务。数据库提交与 outbox 同事务；向量服务失败只影响索引状态，不撤销已保存模板。

本机旧数据到新契约需要显式转换工具和验证报告；不能只改 schemaVersion。首轮用源目录重新提取对照样例，确认信息未丢失后再选择批量重提取或转换。

10．Qdrant 检索与 RAG

第一版每个模板版本一个检索点，以功能、布局、控件、层级和已确认视觉特征构成摘要。完整 JSON、图片与参数保存在 PostgreSQL，查询命中后再读取。

  • 选择中英文适用的 embedding 模型后固定模型版本、维度、距离度量与摘要格式；不得将不同模型的向量混在同一向量空间。
  • payload 包含模板/版本/来源 ID、分类、结构标签、完整性、验证等级与索引代次；筛选字段按查询需要建立索引。
  • 默认检索可用的当前版本，历史版本显式查询。新版本索引成功后再切换可见版本；搜索结果必须标记版本与索引新鲜度。
  • index_jobs 支持幂等 upsert、删除墓碑、超时重试、错误记录和可重建；迟到旧任务不能覆盖新代次结果。
  • 未来图片向量只覆盖真实有预览的模板，记录覆盖率；不可用少量图片声称全库支持视觉检索。

查询路径：需求解析 → 分类/质量过滤 → 语义召回 → 层级、列表方向、控件等结构排序 → 获取证据与完整模板 → Agent 决策 → 重建预检。Qdrant 得分不是可重建或可生产的证明。

模型与本地/云端运行方式、预览生成覆盖率、正式集合命名和性能预算仍是实施前决策项，不在本文虚构已选配置。

14.1 资产身份与字节去重分离

源对象身份为 sourceId + GUID + localFileId；localFileId 以十进制字符串传输，避免 JavaScript 大整数精度丢失。一个图集多个 Sprite、一个文件多个 Clip 必须有独立对象身份。同字节文件可以共享 blob，但不因此合并语义不同的资源身份。

模板内节点/组件采用稳定局部 ID；实例 ID 与被引用模板身份分开。没有可靠源 ID 的对象使用显式合成标识和生成规则版本，不使用会随重命名变化的路径作为永久身份。

保留 sourceSerializationVersion、extractorVersion、adapterVersion、Unity/包版本。未知字段逐项记录“无重建影响／可能影响／阻止重建”，不能统一忽略。

16．版本化装配方案契约

新增 assembly plan，位于源模板和最终产物之间。Agent 提出方案，校验器决定可执行性，UnityCLI 依据固定方案执行。方案不可修改源模板版本。

建议新增 assembly.plans、assembly.plan_versions、assembly.runs、assembly.outputs，作为独立装配职责域；run 引用固定 plan_version，产物引用新资源或模板版本。与生成任务通过 ID 关联，不保存重复源资源。

示例为结构说明，UUID、版本和输入文件必须在正式样例中真实存在。操作白名单包括创建/移除节点、重设父节点、设置支持字段、绑定资源、绑定组件与实例化嵌套模板。设置前校验节点、类型、操作顺序与被引用对象；无效删除或循环禁止执行。

  • 方案输入锁定模板、资源、风格、适配器与验证配置版本，保存规范化哈希。不得在执行时解析为任意“最新”。
  • 仍待生图的槽位不算可执行；生图完成并选定资源版本后生成新的执行方案版本。重试装配不能偷偷重新生图。
  • dry-run 输出解析结果、变更列表、缺失项和兼容性，禁止写入正式资源或覆盖用户场景。
  • 正式执行在隔离环境制作、验证后发布；默认目标已存在则失败。需要替换时显式授权并保留备份/GUID 策略。
  • Unity 文件系统与数据库不是一个事务。执行日志记录 prepared/built/validated/published/registered；中断后核对文件哈希与状态再恢复，不重复覆盖。
  • 相同方案和固定工具输入应生成等价结构、绑定与布局；Unity 序列化字节、粒子逐帧像素或生图像素不默认保证完全相同。

19．正式库首件接入（2026-10-13）

新增 asset-library 命令组，通过 GameAI.Server 专用适配器访问独立 gameai_asset_library 数据库；禁止回退到 Track 连接。首次只接收明确指定的根 GUID 及其依赖闭包，不隐式上传整个导出目录。

19.1 实现入口

  • asset-library migrate --server <服务目录>：专用库建表，迁移校验和防止已应用 SQL 被重写。
  • asset-library upload --server <服务目录> <导出目录> <根GUID>：验证现有 ui-export/1 数据包，显式转换为 ui-template/2，保留原始布局与视觉证据。
  • asset-library index-init --server <服务目录>：读取实际本地模型 digest 和维度，创建独立索引代次。
  • asset-library index --server <服务目录> <profileId>：执行待索引任务，失败可重试，成功 upsert 后回写数据库。
  • asset-library search --server <服务目录> <profileId> <查询文本>：查询真实向量并回读 PostgreSQL。
  • asset-library report --server <服务目录> <版本UUID> <空输出目录>：从服务器生成可读层级、原图、资源参数和诊断报告。

19.2 配置与连接

凭据在服务目录被 Git 忽略的 .env.asset-library 中，字段为 ASSET_DATABASE_URL、ASSET_QDRANT_URL、ASSET_QDRANT_KEY、ASSET_OLLAMA_URL、ASSET_EMBEDDING_MODEL。不得复制真实值到文档。当前采用 SSH 回环转发；game-cli/tools/connect-asset-library.ps1 提供连接入口，转发端口为 15439、16339、11439。隧道关闭后需重新连接才能执行远程命令，静态验收报告不受影响。

19.3 明确限制

第一版不是纲要全部功能完成。分类来自名称/结构启发式；风格标记 not_analyzed；动画/特效保存源证据但不代表可重建；当前只提供模板版本语义候选排序，未完成结构重排与固定检索评测集。资源参数按原资源图保留，复合资源子对象 fileId 在绑定中保存，尚未全部拆成独立子资源身份。

只索引当前首件及其依赖，暂不自动推广到复杂 UI 或全库。不同模型 digest 创建不同 profile；历史版本切换和删除墓碑仍需在批量生产前完成。资源版本暂采用闭包级哈希，正确固定依赖但可能因其他资源变化产生保守的新版本，后续优化细粒度去重。

源图片成功入库与完整视觉重建是不同验收。首件 LoginView 为 reference-only，含 132 个节点、37 项资源、28 张可查看源图片；必要依赖 QueueConfirmView 25 个节点。保持所有能力缺口可见，不以向量检索命中冒充完整生产。

20．授权变更校验（2026-10-13）

最终结果依据“原始模板＋用户授权变更”验收。换皮默认保留；明确要求允许增加、删除、布局和功能调整。以节点和组件 ID 比较字段，而非只比较数量。自定义脚本不迁移不等于删除入口。

工具入口

GameCLI ui-library guard --baseline source.json --candidate candidate.json --output audit.json
GameCLI ui-library guard --baseline source.json --candidate candidate.json --approval approval.json --output assembly.json
UnityCLI --project app/client prefab restore --json assembly.json --prefab Assets/.../UIName.prefab --dry-run

audit 只列差异，不能作为自动批准。approval 使用 ui-change-approval/1，固定源哈希、目标路径、真实指令来源和逐项 before/after。严格匹配后生成 ui-assembly/2；Unity 在贴图导入和预制写入前重新验证。正式创建省略 --dry-run，已有目标仍须显式 --replace。

实测

  • 24 项离线提取、装配和变更校验断言通过；明确新增、删除、改名通过，未授权状态和同数量节点替换拒绝。
  • Unity 编译和无变更封装 dry-run 通过；篡改 active 后即使重新计算哈希也被拒绝。
  • SV 原始登录与上一版精简候选的差异被拒绝，没有写入新的预制。

边界

该校验确保结果与给定清单一致，不证明授权文本真实性；宿主仍必须核对真实用户指令。原始 restore/create 入口保留，无基线新建不强制使用。已有模板改造技能禁止降级入口绕过；Track 服务强制审批身份绑定、功能运行测试和所有入口统一门禁尚未接入。
