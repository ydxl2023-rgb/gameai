一、当前基线

单机正常流程已验证：策划生成 HTML、人工审批、PM 拆分、开发创建并发布控制台程序、QA 两次启动验证。QA 通过后保留最终人工验收。PostgreSQL 是业务状态的唯一可信来源。

已有固定角色、依赖检查、执行租约、QA 缺陷与原 Agent 返修、按批准版本自动推进、工作流事件 Output。远程节点与最终人工验收入口仍需完善。

二、优化项与验收标准

优先级事项当前缺口建议方案完成标准
P0最终人工验收QA 通过后主任务仍待验收，缺少正式人工收尾入口。展示产物与 QA 报告，支持验收通过或退回，记录人员、意见和交付版本。通过后主任务正式完成；退回产生可追溯的返修任务，记录全过程。
P0异常执行恢复服务中断、结果回写失败或租约失效后，执行可能长期占用。增加执行核实、结果重传、确认终止和重新执行；优先核实原进程。中断与重启不重复启动任务，迟到结果不能覆盖新执行。
P0文档与产物归档Hello World 日志出现本地需求 HTML 缺失；交付依赖本机目录。执行前落盘已批准 HTML 并核验哈希，统一归档源码、资源、报告和发布文件。开发与 QA 使用同一批准版本与可追溯产物；缺失文件明确阻塞。
P1状态与执行阶段测试通过、报告整理、任务结束、人工验收的含义容易混淆。区分 Agent 工作状态、执行阶段、任务交付状态和 QA 结论。Agent 显示工作或空闲；异常占用、停用等原因可查询。
P1调度可靠性审批恢复只扫描 queued；前 100 项均阻塞可能遗漏后续就绪任务。持久化调度事件，核对 pm 阶段未决作业，分页选取就绪任务与公平调度。重启恢复不重派；第 101 项就绪时仍可调度。
P1执行日志当前每 3 秒获取快照，只展示最近 500 条。增量事件游标、历史分页、推送更新、阶段耗时及任务跳转。断线恢复不重不漏，查看历史不被新日志强制滚动。
P1确定性验收证据文件与哈希已校验，但测试结论仍较依赖 Agent 返回。标准执行器采集编译、退出码、标准输出与耗时，Agent 分析证据。结论可由原始记录独立复核，不能仅凭模型声明通过。
P1文档与实现同步纲要存在旧阶段说明、待实现能力及刷新周期相互矛盾。建立已实现、部分实现、未实现能力表，标注验证日期与来源。查询同一能力时能得到唯一的当前实施状态。
P2多节点与隔离并行只支持服务器本机固定 Agent，同一目录串行执行。常驻 GameCLI Worker、容量管理、独立工作区与同角色多 Agent。不同任务可并行；同一任务不重复执行；返修仍定位原 Agent。

三、建议实施顺序

  1. 补齐查看产物与 QA 报告、人工通过或退回、主任务收尾。
  2. 验证重启、断线、超时、重复回传和迟到结果恢复。
  3. 统一文档落盘与产物版本，增强确定性证据。
  4. 完善调度、日志和文档基线，再扩展隔离并行及远程 Worker。

四、当前显示优化范围

本轮仅调整项目总览列宽拖动与记忆、Skills 单列对齐与人工添加、Agent 状态“工作／空闲”。技能添加保留主技能与现有辅助技能，仅选择已登记辅助技能，工作或待核实期间禁止变更，下次执行生效，不授予额外业务权限。

上述优化清单留待后续逐项确认和开发。参考 服务实施基线 与 技术开发纲要。
