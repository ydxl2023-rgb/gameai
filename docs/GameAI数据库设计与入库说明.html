1. 范围与数据源

本机 PostgreSQL 18；数据库 gameai，业务模式 gameai。当前 26 张业务表，另有 public.gameai_migrations 迁移登记表。新 Track 的数据库模式直接读取数据库，不再把静态 JSON 当作权威状态。旧外部任务系统集成已移除，没有与平台并存的旧派工通道。

查询在一致性只读事务中完成。数据库不可用返回错误，不回退为演示数据。文件内容独立存储，数据库记录文件引用与核验信息；没有将现有完整需求文档假称为已上传附件。

2. 表结构与字段字典

主键一般采用 uuid；时间采用带时区时间戳，展示时转换本地时区。大整数编号通过字符串传输。版本正文、扩展结果采用 jsonb；项目、任务、角色与依赖采用关系表及外键约束。

主链：项目 → 需求 → 不可变需求版本 → 人工审批 → 计划版本 → 任务 → 依赖／执行 → 产物／评论。工作节点与 Agent 分开；人工账户与 Agent 分开。

3. 入库内容与验证

  • 1 个测试项目 DEMO，明确设置 is_test=true。
  • 1 项七日登录需求、2 个节选版本；没有伪造历史审批。
  • 1 个草案计划、1 个计划版本、4 项任务、3 条依赖。
  • 6 个 Agent、6 个工作节点；节点默认禁用、离线，任务进度归零，无运行执行与租约。
  • 6 条读取授权，未授予任务写权限；1 条导入审计记录。
  • 角色与权限字典已入库；没有创建可登录用户，没有导入旧系统任务。

已验证：重复迁移与重复导入不覆盖；新连接重新读取内容一致；版本修改、循环依赖、非法进度、Agent 审批授权、无权人工审批、同任务重复运行被拒绝。Track 数据库账号仅具备读取权限。约束测试在事务中回滚，不残留模拟执行。

4. 配置与维护

命令工作目录：app/client/LocalPackages/com.oathx.gamecli/GameCLI~/GameCLIServer。

入口用途
.env.databaseTrack 专用只读账号及项目配置，已配置并被 Git 忽略。
.env.database-admin迁移所有者账号，只供本机维护命令使用；已忽略。
npm run db:migrate按文件序号事务执行迁移；验证已执行文件校验和，禁止改写旧迁移。
npm run db:seed显式导入测试项目；项目存在则跳过，绝不自动覆盖。
npm run db:status查询数据库记录数量。
npm run test:database数据库约束与持久化验证；本机需先完成迁移和测试种子。
npm run build:track / npm run start:track构建／启动工作台；默认端口 8090，可用 GAMECLI_TRACK_PORT 覆盖。

只读接口 GET /api/track/snapshot 与 MCP 两个读取工具共享同一查询仓储；旧 /api/track/demo 为兼容别名，也读取当前配置数据源。配置按服务目录解析，stdio 不依赖启动工作目录。显式设置 GAMEAI_STORAGE=demo 可运行离线演示；正式配置为 postgres。

密码不写入源码、日志与文档。迁移与服务使用独立数据库账号，服务不使用 postgres 超级用户。换机器需自行创建数据库与两个账号，再填写本地配置；由所有者向只读账号授予模式 USAGE 和表 SELECT。备份采用 pg_dump 自定义格式，恢复先在独立测试库验证；数据库和文件存储一起备份。

5. 后续实现边界

  • 已完成实际表结构、事务迁移、测试数据导入及 Track/MCP 数据库读取。
  • 正式登录与服务端会话尚未接入，页面审批及权限修改按钮在数据库模式禁用；客户端身份选择不能作为授权依据。
  • 审批发布、完整附件核验、PM 拆分、依赖就绪派工、心跳租约、结果回写及事件发件箱消费尚待业务服务实现；存在表结构不等于这些流程已经运行。
  • 计划发布必须核验批准版本及附件、任务交付标准和依赖；派工需在事务中验证权限、节点容量、依赖、租约隔离代数并写入发件箱。当前没有开放此写接口。
  • 测试项目不自动转正式项目，不执行任何真实 Agent 或开发任务。

6. 手动配置 Agent（迁移 002）

项目总览和 Agent 分页提供添加入口，列表复用同一组件。输入名称、角色、节点、主技能、辅助技能、并发容量与启用状态。保存后转到 Agent 分页；总览只显示实际执行中的实例。

维护：npm run db:migrate；npm run db:sync-skills。目录同步不改写已绑定的技能版本；技能内容变化后，需先同步目录再新建配置。绑定文件版本不代表节点已安装，节点上线校验和派工仍待接入。
