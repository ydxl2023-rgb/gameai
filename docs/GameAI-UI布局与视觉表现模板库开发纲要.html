1. 目标、边界与已确认决策

建设可持续扩充的 UI 布局与视觉表现模板库。导入现有 Unity 预制，按功能检索多个候选，再由 Agent 提出组合与映射方案，交给确定性工具生成目标项目预制。

首批来源：G:/Works/SV/Development/Project/Assets/data/UI。只读扫描发现 2,833 个 .prefab；这是本次扫描数量，不代表已完成入库或兼容性验证。

  • 核心复用对象是布局、嵌套组件与视觉表现，不迁移原项目业务 C# 代码。
  • 正式布局 JSON 允许目标工程支持的 Unity 标准组件和官方包组件；禁止携带源项目自定义 C# 路径、脚本 GUID、业务组件实例、业务事件方法名及未解析对象引用。标准组件使用注册表逻辑类型，不保存源工程脚本 GUID。
  • 嵌套预制、特效、动画、贴图必须保留依赖与绑定关系，使用库内稳定 ID 和固定版本。
  • 特效贴图以原始二进制存入数据库；Shader 保存可理解的实现描述，不直接复用原 Shader 实现。
  • 源工程只读；目标生成失败不得污染源资产。未知或不支持的内容显式标记，不静默丢弃。

本文是后续开发基线 v1.3，尚未实现全量提取、资源入库或 RAG 服务；下文表名、JSON 字段和命令为拟定契约。

2. 总体架构与职责

模块职责
提取器读取源预制、解析完整层级与嵌套覆盖，输出中立结构；适配已识别的自定义布局组件。
资源登记器递归收集特效、动画、贴图及材质依赖，分配资源 ID、版本和内容哈希。
PostgreSQL保存模板索引、版本化 JSONB、贴图二进制、依赖图、检索数据与生成溯源。
检索服务功能过滤＋全文检索；后续加入向量召回及结构重排，返回候选和差异。
Agent补充可审核语义；比较候选、提出组合及 Shader 实现方案，输出受约束的参数。
目标生成器校验 JSON、资源与节点映射；通过 Unity CLI 创建/组装预制及兼容视觉实现。
QA检查结构、引用、布局适配及实际效果，保存证据，不用语义相似度代替验收。
源工程（只读） → 提取/归一化 → 版本化模板库
需求 → 功能分类 → 候选检索 → 结构比较 → 组合方案 JSON
组合方案 → 兼容性校验 → Unity CLI → 白模 → 美术补齐 → 最终装配 → QA

GameCLI 负责执行工具与上传结果，GameCLIServer 负责数据、权限、审批与调度。实现时沿用 C#/.NET CLI 和 Node.js 服务边界，不另建本地编排器。

3. UI 布局数据契约

3.1 唯一结构：资源清单＋节点

顶层业务主体固定为 resources 与 prefab，schemaVersion 为格式元数据。不另设顶层 bindings；嵌套实例、动画和特效绑定就近保存在所属节点。来源、分类、标签、检索描述和导入日志另存数据库。

  • resources 是资源别名字典，统一使用 kind、id、version 描述预制、特效、动画、贴图和 Shader 描述；固定版本，禁止隐式 latest。
  • prefab.nodes 是扁平节点表。只用 parentId 与 siblingIndex 表达层级，不再同时维护 children。必须有且仅有一个根节点，rootNodeId 指向它；节点 ID 唯一，父关系无环。
  • kind 仅区分 Node 与 PrefabInstance；semanticRole 是可选语义标签，不决定组件。不能同时用节点 type 与 components 重复定义 Button 等组件。
  • components 是标准组件配置的唯一依据；rect 是 RectTransform 的唯一来源，不在 components 再存一份 RectTransform。
  • effects 默认挂在所属节点；animations 的 targets 明确绑定目标。trigger 为 null 时表示未知，不能自行补出触发业务。

3.2 标准组件与代码依赖边界

类别处理规则
Unity 标准组件保留 Image、Button、Toggle、ScrollRect、RectMask2D、布局组件、Animator 等支持的类型与参数。
官方可选包例如 TMP，记录逻辑类型、包版本要求及目标兼容性；缺包时标记需要适配。
源项目自定义组件不直接迁移。已确认布局语义可转为标准组件；未知行为记录在诊断中，不嵌入生产 JSON。
标准组件中的业务引用保留按钮等本体，剥离旧 onClick 脚本方法；Animator 中自定义 StateMachineBehaviour 同样需要适配。记录待接入的语义交互接口，不猜测实现。

3.3 组件注册表

提取器和生成器共享同一份版本化注册表：逻辑类型、支持属性、属性类型、默认值、取值范围、引用类型、包/引擎版本要求与适配器。未知字段必须拒绝或转为诊断，不静默忽略。

{
  "kind": "Node",
  "semanticRole": "reward-list",
  "components": [{
    "id": "scroll",
    "type": "unity.ugui.ScrollRect",
    "properties": {"horizontal": false, "vertical": true, "inertia": true},
    "references": {
      "viewport": {"nodeId": "rewardViewport"},
      "content": {"nodeId": "rewardContent"}
    }
  }]
}

3.4 布局值与计算值

保存参考分辨率、Canvas 缩放设置、anchorMin/Max、pivot、anchoredPosition、sizeDelta、局部变换及自动布局参数。明确单位和坐标约定。静态序列化值用于生成；引擎计算后的屏幕尺寸仅作为派生测量数据，记录测量分辨率与环境，不覆盖原值。

SizeDelta 可为负值，不能当作实际宽高直接使用。LayoutGroup、LayoutElement、ContentSizeFitter 的排列、间距、padding 与约束必须保留；单个预制不能确定的画布参数应标记未知，不猜测。

3.5 可重建等级

完整支持：全部布局、组件与引用可在声明的目标环境重建；需要适配：存在明确缺口；仅供参考：尚不能可信重建。另记录验证状态，不能把“支持提取”当成“已验证效果”。检索优先完整支持的候选。

4. 嵌套模板、实例覆盖与依赖图

商店窗口可以引用道具框，奖励列表可以引用卡片模板。被引用模板独立入库，父模板只保存固定版本引用和实例差异。

嵌套实例统一采用第3节的 kind=PrefabInstance、resourceRef 和 overrides，不另存 templateRef 或第二套实例绑定清单。

  • 实例覆盖以稳定节点 ID 为目标；支持可验证的属性覆盖、子节点新增和删除。保留覆盖顺序，禁止只按同名节点匹配。
  • 导入时解析 PrefabVariant、PrefabInstance 及 inherited/stripped 对象；未展开的模板不能标记为可无损重建。
  • 跨嵌套引用使用 instancePath（实例节点ID数组）＋nodeId；当前模板节点使用 nodeId。覆盖目标相对被引用模板解析；禁止靠名字或拼接层级路径猜测。引用固定版本，不能隐式取 latest。缺失引用、循环引用和无效覆盖必须阻止生成。
  • 保存完整依赖闭包及依赖哈希，生成时锁定所有使用版本。

5. 特效索引与参数文件

特效是一类独立版本化模板。UI 引用 effectId/version，实例保存挂载节点、局部变换、排序和明确的播放条件。

参数组提取内容
核心时长、循环、空间、生命周期、初速度、尺寸、颜色及随机分布。
发射/形状速率、爆发、形状、边界与方向。
随时间变化速度、力、颜色、尺寸、旋转、噪声等曲线与模式。
渲染网格/广告牌、排序、材质表现引用、贴图序列、Trail等。
嵌套子发射器、子特效、挂载层级、依赖版本。
验证已提取模块、不支持模块、目标管线兼容性和实际验证状态。

“完整参数”以明确支持清单为准。曲线保存关键帧、切线、插值、wrap、常量/双常量/双曲线等模式；不能仅存采样值后宣称精确还原。Mesh、贴图和其他必要资源未登记时，特效只能处于待适配状态。

6. 动画索引与节点绑定

AnimationClip 与 Animator 状态机分开登记。片段保存时长、循环、帧率、属性轨道、关键帧和插值信息；状态机另存参数、状态、过渡、混合树及默认状态。

  • 轨道目标使用语义 bindingKey，由实例映射到 nodeId；生成器再转换为目标工程的动画路径。
  • 保留对象引用曲线中的资源版本，如逐帧 Sprite 动画。
  • 动画事件、StateMachineBehaviour 和自定义属性若依赖旧代码，不复制方法名或脚本引用到中立模板；记录为需适配的行为。
  • 仅在序列化证据明确时记录触发条件。由 C# 决定的点击播放逻辑不可猜测。

动画和特效绑定统一放入所属节点的 animations/effects，resourceRef 指向顶层资源别名。跨模板目标使用 {"instancePath":["rewardItem"],"nodeId":"quantity"}；生成器校验目标实例与节点存在后转换成引擎路径。

7. 贴图二进制与 Shader 实现描述

7.1 贴图入库

使用 PostgreSQL bytea 保存原始文件字节，记录 SHA-256、MIME、字节数、宽高、通道。文件原始字节按哈希去重；颜色空间、wrap、filter、alpha用途等作为引用的使用设置，同一文件可有不同用途。上传配置大小上限，服务校验解码结果和哈希；不要把 Base64 大图嵌入布局 JSON 或向量文本。

7.2 Shader 描述

保存视觉目标、纹理槽位及通道含义、参数类型/默认值/范围、采样与数学步骤、渲染状态和已知限制。可保留原 Shader 名称与哈希用于溯源，但不依赖其源代码、include、编译产物或源工程类型。

{
  "name": "流动溶解光效",
  "purpose": "纹理纵向流动并按噪声阈值溶解",
  "parameters": {
    "scrollSpeed": {
      "type": "float2",
      "default": [
        0,
        0.2
      ]
    },
    "threshold": {
      "type": "float",
      "range": [
        0,

      ]
    },

Shader Graph、自定义光照和平台宏可能无法自动转换；保留待确认说明及可用参考效果，不虚构实现。

8. PostgreSQL 存储模型（拟定）

表主要内容
ui_templates稳定 ID、功能分类、标签、名称、源工程标识＋源GUID。
ui_template_versions模板版本、schemaVersion、布局 JSONB、源哈希、提取器版本、兼容性。
effect_templates / effect_versions特效索引及版本化完整参数 JSONB。
animation_templates / animation_versions动画片段与状态机索引、轨道和绑定描述 JSONB。
shader_descriptions / shader_description_versions视觉实现描述、参数、渲染状态、来源与可信程度。
texture_blobs哈希唯一键、原始 bytea、MIME、尺寸、字节数。
texture_assets / texture_versions语义名称、来源与 blob 引用；使用设置由材质/实例引用携带。
asset_dependencies源资源版本→目标资源版本、用途槽位、依赖关系与验证结果。
search_documents / search_embeddings对应资源版本、语义描述、结构特征、描述哈希、模型/维度及向量。
import_runs / extraction_issues导入来源、状态、解析警告、失败项；诊断与生产布局分离。
generation_records目标任务、候选列表、最终选择、版本锁定清单、映射和生成证据。

数据库约束：资源版本不可变；同源＋同内容导入幂等；引用目标版本必须存在；二进制先校验再发布元数据；删除被引用版本应拒绝或显式归档。多来源工程使用不同 source_project_id，避免 GUID 冲突。

首版可不建向量列，但必须提前保存可重建的检索文本及其哈希。后续迁移按模型维度设计索引，不假定所有模型共享一个向量空间。

9. 功能分类、候选选择与 RAG

先找到“登录”功能，再从多个登录模板中比较：设备一键登录、账号密码登录、选服登录等；功能类别不是唯一模板，不合并不同实现。

  1. 根据需求提取功能、横竖屏、必要控件和目标兼容条件。
  2. 结构化过滤不可用候选，全文召回功能名称与标签。
  3. 后续加入语义向量召回，并合并去重。
  4. 按功能覆盖、布局、层级结构、嵌套依赖与改造成本分别重排。
  5. Agent 读取少量候选完整 JSON，输出选择理由、缺失控件和修改方案。

不将完整坐标、GUID 和重复节点 JSON 直接作为唯一向量文本。语义描述与工具事实分开保存；模型生成标签标记为推断。向量只是检索索引，不是生成的真实数据源。

检索单元为完整窗口和可独立复用的弹窗、卡片、列表项、特效、动画；不把每个 Text/Image 切成独立知识片段。保存父模板关系和节点定位信息。记录 embedding 模型、版本、维度及输入文本哈希，内容改变后仅重建受影响检索条目。

10. 接入 GameCLI 生产流程

  1. Design 编写并由人工批准需求，明确项目视觉规范版本。风格在目标生成阶段应用，原模板布局与可选视觉资源分开；不强制新项目沿用旧皮肤。
  2. PM 按独立窗口拆分白模、美术及最终装配任务，避免因模板节点多而过度拆单。
  3. Prefab Agent 查询模板库，形成模板引用、节点映射、实例覆盖和缺口清单。
  4. 生成器校验版本、依赖图及支持能力，通过 Unity CLI 创建目标白模。
  5. Art 复用符合规范的视觉资源；缺少或不兼容时按已批准风格补齐，不要求所有资源重新生成。
  6. Prefab Agent 绑定图片、特效和动画；工具负责资源导入、路径重映射及校验。
  7. QA 验证真实结构和运行效果，保存证据；编排器按现有权限和审批规则推进。

Agent 负责选择和映射决策，工具负责可重复执行。不存在的资源引用、未知字段、循环依赖及不支持属性必须在生成前拒绝。历史任务使用锁定版本，禁止隐式升级模板。

11. 分阶段实施与验收

阶段范围通过标准
P0 契约与样例统一中立JSON、数据库结构和支持矩阵；一个完整窗口＋一个嵌套列表项。布局JSON无业务C#依赖；来源/诊断隔离；引用可解析，属性单位明确。
P1 布局索引只读批量扫描、分类与增量导入，提取标准UGUI和必要自定义适配。重复导入不重复建版；嵌套覆盖准确；未知组件被标记，原工程哈希不变。

12.2 存储与幂等

已创建 sources、templates、versions、dependencies、imports 六张表。来源工程＋源 GUID 区分模板身份，版本保存 JSONB、源依赖哈希、提取器/Unity 版本、诊断和兼容等级。规范化内容及依赖版本参与指纹；事务和唯一约束保证重复、并发导入不会重复建版。更新产生新版本，不覆盖旧 JSON。分类默认 unclassified，不依据名称猜测已确认的功能。

12.3 明确边界

  • 现阶段支持节点、RectTransform、标准组件的序列化标量/向量和本地节点引用。属性键仍是 Unity 序列化属性路径，尚未完成跨 Unity 版本的逻辑属性注册表。不能直接传给 prefab create。
  • 位置节点 ID 只保证单个不可变版本内稳定，跨层级调整的节点身份匹配尚待实现。
  • 嵌套预制会递归导出并建立版本依赖；实例覆盖目前保存为诊断证据，完整覆盖/增删节点适配尚未完成，等级为 reference-only。
  • 未知组件、旧业务回调及未支持的资源属性被记录为诊断，不进入标准组件的生产字段。字体、贴图、材质、动画和特效完整参数/二进制入库尚待实现，不承诺视觉无损。
  • supported 仅表示本轮没有发现不支持字段；仍须实际重建验证。reference-only 禁止自动作为最终生产结果。

13. 多项目离线采集入口（2026-10-13）

采集主入口现在是 C# GameCLI，使用 YamlDotNet 解析文本序列化的 Unity 资产。来源工程不启动 Unity、不安装 Unity CLI、不执行源 C# 脚本。现有 Unity 导出入口保留为目标工程的校验工具。

GameCLI ui-library export \
  --input "G:/Works/SV/Development/Project/Assets/data/UI" \
  --output "<新的空导出目录>" --source-key sv --limit 20

GameCLI ui-library validate --input "<导出目录>" --server "<GameAI.Server>"
GameCLI ui-library import --input "<导出目录>" --server "<GameAI.Server>"

--input 接受单个 .prefab 或目录；不传 --limit 时扫描全部。source-key 是人为指定并持续复用的来源工程身份。自动定位上级 Unity 工程，扫描 Assets、Packages、LocalPackages 内的 .meta 建立 GUID 索引；不遍历重解析点，不写入源工程。外置包未落在这些目录时会报告缺失，不猜测引用。导出目录必须在来源工程外。

13.1 解析与引用约定

  • fileID 按字符串解析，避免超过 JavaScript 精确整数范围时损坏。
  • 递归解析嵌套预制，将实例层级展开为带实例前缀的节点 ID；prefab.instances 保留 instanceId、resourceRef 和 rootNodeId，resources 保存源预制及版本。数据库依赖表绑定库内固定版本。
  • 应用已支持的名称、标量、向量属性及节点引用覆盖。数组规模调整、删除节点/组件等复杂结构变化仍报告人工复核；不宣称无损还原。
  • 官方脚本 GUID 映射来自已安装的 UGUI/TMP 包并内嵌分发；不把来源工程中同名自定义脚本误认为官方组件。
  • 外部纹理/材质/动画引用目前保存为缺项诊断，未完成二进制入库。FBX 模型预制保留明确标注的占位节点；二进制 .prefab 和找不到的源预制作为失败项。
  • 节点结构与标准组件属性仍是布局快照，不直接兼容 prefab create 输入。全部离线结果初始为 reference-only，实际重建验证后才能提升状态。

视觉依据提取与入库（2026-10-13）

流程固定为：原始预制提取 → 白模重建 → 读取原始视觉依据 → 生成或适配最终资源 → 填充预制 → 视觉验收。白模布局与视觉证据分开保存，原始项目只读，不携带自定义业务脚本。

信息当前保存内容
贴图与字体源二进制、SHA256、导入参数；PNG 尺寸；Sprite 切片、九宫格边界、Pivot、PPU 等按原始 importer 保存。可选字体包资产需要专用适配。

Shader源指纹、可识别渲染状态和实现线索；不保存源代码用于直接执行。线索不是完整算法，标记 analysis-required，未来需分析采样公式和目标渲染管线。

一键静态重建（2026-10-13）

正式命令：GameCLI ui-library restore --version 90 --server <GameAI.Server目录> --project <当前Unity工程> --output <新的输出目录>。重复写入已有目标预制必须显式加 --replace。--dry-run 只准备数据库资源和缺项报告，不修改 Unity 资产；正式执行在导入后另执行 Unity dry-run。

数据库版本 ID → 校验资源与绑定 → 导出内容寻址贴图和字体 → UnityCLI asset import → prefab restore dry-run → 正式重建 → prefab inspect → 实际预览。产物包含 plan.json、restore.json、result.json、preview.png 和 index.html。输出目录必须为空，旧证据不覆盖。未走 Track。

单图 Sprite 和字体自动映射。SV 指定文字组件 GUID 采用独立的展示字段白名单适配，只保留字号、颜色、对齐和原文，不执行其脚本。新增 TTC 字体证据支持。原文为空或 LID 编号时保留并警告，不能冒充完成本地化。

动画/特效、未支持视觉资源、图集切片以及无活动可视节点会产生 blockers；不强行显示源隐藏节点。未知脚本保留 warnings，状态为 restored-with-warnings，需人工复核。当前不宣称任意项目完整无损还原。

实测数据库版本90自动恢复5张贴图和2份字体；预制无缺失引用。版本65动画/特效门禁阻止执行，隐藏控件样本触发无可见节点门禁。13项服务端测试及11项离线提取断言通过。

模板检索优先流程（2026-10-13）

需求描述 → 功能分类筛选 → 对比结构、预览和限制 → 人工或 Agent 明确选择 versionId → restore 预检查 → 白模调整 → 视觉填充与验收。检索不启动 Unity、不创建 Track 任务。

GameCLI ui-library search --query "带确认和关闭按钮的提示窗口" --server <GameAI.Server目录> --output <候选报告目录>。输出 index.html 和 candidates.json。根据候选 versionId 调用已有 restore；保留版本绑定，不用浮动模板名称替代版本。

首版使用名称/路径推断 dialog、login、shop、inventory、reward；其他归为 unclassified。按真实组件提取按钮名、滚动方向、布局类型、节点数、根 RectTransform 和层级摘要。明确功能类别时优先限定同类别，再评分结构匹配；零分不返回，最多10项，每模板只返回最新版本。

分类为启发式，需要复核；匹配分数不是视觉相似度，不是向量 RAG。伸缩根节点 sizeDelta 为零不表示窗口实际尺寸为零，应结合 anchors 和宿主画布解释。资源缺项数量不等于完整重建检查，候选仍须执行 restore 预检查。

ui_library.catalog 保存版本化结构索引；ui_library.previews 保存按模板版本关联的 PNG。成功重建后自动登记预览，没有预览的候选明确标注。搜索时刷新最新版本结构索引。首版使用本机命令和 HTML 报告，暂未接入 Track 页面或全量向量检索。

实际查询在17个最新模板版本中首位返回 TipsView（版本90），命中提示窗口、两个按钮、关闭按钮与确认按钮。16项服务端测试通过。
