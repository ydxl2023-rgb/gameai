1. 范围

复用 GameCLIServer HTTP 路由扩展，新增 TypeScript 模块和模拟启动入口。原 start.bat、JIRA Webhook 和 WebSocket 行为保持兼容。测试入口不读取 .env，监听本机 8090，项目为 DEMO；不读取或写入 JIRA，不启动 Agent。

界面包含三条模拟任务、紧凑英文表头、中文状态、刷新按钮、服务器时间、请求编号和 Output。刷新失败保留旧数据并提示过期；宿主桥接和网络调用有超时，禁止重复点击产生并发刷新。

2. 启动

本地 Codex 内嵌验证使用 stdio 自动启动。首次执行 npm ci 与 npm run build:track，然后运行 pwsh.exe -File scripts/register-codex-track.ps1。完成注册后不需要手动保持 HTTP 服务运行。下面的 start:track 仅用于独立 HTTP 预览测试。

从仓库根目录进入服务目录，执行：

cd app/client/LocalPackages/com.oathx.gamecli/GameCLI~/GameCLIServer
npm ci --ignore-scripts --no-audit --no-fund
npm run build:track
npm run start:track

Windows 也可运行该目录中的 start-track.bat。端口冲突时更改 GAMECLI_TRACK_PORT，并同步本地插件的 .mcp.json 地址后重新安装。独立测试服务不替换现有 8088 服务。

  • 浏览器预览：打开 GameAI Track。
  • MCP：本机 /mcp，使用 Streamable HTTP 无状态请求响应。
  • gameai_track_open：返回模拟数据并关联 UI 资源。
  • gameai_track_snapshot：返回模拟快照，不重复创建组件。
  • 所有验证路由限定本机访问。部署到远程或接入真实数据前需另行完成身份及权限设计。

3. 插件接入

插件安装成功不等于当前对话已加载 MCP。出现只有浏览器预览、没有工具的情况时，在服务目录执行下列命令。脚本检查本地构建文件，再通过 Codex 官方 CLI 注册由宿主管理的 stdio 入口，不覆盖其他 MCP。

pwsh.exe -File scripts/register-codex-track.ps1

可分发源文件在包内 CodexPlugin~/gameai-track，含标准清单、.mcp.json、入口 SKILL 和 UI TypeScript 源码。本机已安装 gameai-track@personal。UI 构建产物由服务提供，不依赖插件缓存中的源码执行。

安装后还需完成用户级 MCP 直接注册。已在本机注册 stdio 入口。Codex 自动启动 MCP 子进程，不依赖临时 8090 服务和 HTTP 代理；插件内不再重复声明 HTTP MCP。若桌面当前对话未加载工具，退出并重新打开 Codex，让应用重新读取配置。之后选择 GameAI Track 插件，输入“打开 GameAI Track 接入验证面板”，调用 gameai_track_open。当前旧对话不保证动态加载新工具。必须看到组件并点击刷新，才能确认 Codex 内嵌接入成功；浏览器打开和 MCP 返回 JSON 均不能替代此验收。

本机个人源由插件生成工具维护；修改后复制源文件到个人插件目录，再使用 plugin-creator 的缓存版本更新与重新安装流程。不要手工改动市场清单。已确认本机 CLI 将个人源的 ./plugins/gameai-track 解析到用户目录下 plugins/gameai-track。

4. 验收记录

2026-09-28 排查：重启后的桌面日志记录 gameai-track 初始化 HTTP 502，且 8090 已无监听。此前临时 HTTP 测试进程未能随宿主恢复。已改为 Codex 管理的 stdio 子进程；新增测试验证无 HTTP 服务时仍可发现工具、调用并读取 UI 资源。该修改只影响本地 UI 探针，不改变生产云端 WebSocket／HTTP 架构。
