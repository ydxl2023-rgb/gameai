# 移动平台需求规范

- 当前工程严格限定移动平台，所有功能和资源以触屏操作为前提，无需再次询问是否面向电脑。
- 禁止设计或输出右键菜单、鼠标操作、键盘快捷键、悬停等桌面交互。不能把桌面方案作为建议或备选写入单据。
- 使用点击、触屏拖动等移动交互。额外手势或功能入口只有在明确需求支持时才作为确定规则；缺失时在对话询问，不编造已批准方案。
- 背包拖动描述为触屏拖动；丢弃可采用触屏按钮方案，但按钮位置、丢弃数量及确认方式不能因平台约束而自动视为已批准。
- 美术需适配触屏可点击区域、移动端界面可读性和拖动反馈；未给定屏幕尺寸或资源规格时，不擅自写死数值。
- 测试操作必须能在移动端完成。该技能只约定平台约束，单据排版由调用角色另外加载对应技能。

## 默认领奖成功交互

移动端领取成功后直接弹出奖励窗口：顶部显示“领取成功”，中部为实际发放的道具列表（图标、名称、数量），底部小字“点击任意地方退出”。不设置确定按钮。点击奖励层任意位置关闭该层并返回原界面，关闭点击不得穿透触发下层控件。仅收到成功结果或查询确认已发放后展示；明确失败或结果未知时展示对应提示，不伪造成功。重复展示或关闭不再次发奖。线框、控件说明和验收必须一致；这是默认交互，用户对具体功能明确另作规定时以其规定为准。

## 默认明确失败反馈

明确业务失败时只显示失败原因提示条，不打开可操作的失败弹窗。提示条为横向长条，从屏幕中间出现，向上飘动一段后消失；不带确认、关闭或重试按钮，不可点击，不阻塞正常界面操作。原界面根据服务器结果同步状态。不要擅自规定未经设计的固定时长和位移像素。

操作交付标准必须写明该触发、显示、上浮及消失过程；第四节动画需求必须列出提示条的位移和消失表现，不能同时声称本期完全无动画。测试覆盖失败原因正确、无按钮、上浮消失及不阻塞交互。

网络异常、断线、超时与业务失败统一使用上述原因提示条，不设置独立网络异常描述区、弹窗或重试按钮，不增加专门的用户操作。网络恢复后由系统自动查询权威状态；用户再次进入原业务界面时也同步查询。

表现统一不等于业务结果相同：响应丢失仍属于结果未确认，提示使用“网络异常，领取结果确认中”等准确文案，不声称领取已失败。核对已发放则恢复原成功结果；确认未发放且有效才恢复原领取入口；到期按结算规则处理。核对失败时不得自动重复提交发奖请求。普通业务按钮不承担未经核对的重复发奖。操作说明、线框和测试不得残留独立网络异常或重试控件。
