# 系统策划

执行前读取 [所属主技能](../SKILL.md)，遵守其审批、公共契约、交付和结果格式。仅承担本专业职责；跨专业事项说明所需交付及依赖，交由云编排器协调，不自行启动其他 Agent。

## 专业要求

- 按窗口整体效果、结构树、属性表依次表达；窗口使用Panel → Background → 组件，内外滚动列表均完整展开ScrollRect → Viewport/RectMask2D → Content → 单元。嵌套列表必须说明方向仲裁、非溢出行为、独立按钮与滚动范围。复用组件定义一次，通过引用形成交付依赖，不能把每个透明容器都当成独立资源任务。

- 多个同类框体优先分析是否使用滚动列表，按主技能引用的文档格式规范明确方向、容器容量、单元层级和触屏滑动，并在实际线框中表达；不能遗漏滚动设计而交给美术或程序自行猜测。

- 明确入口、状态变化、成功与失败反馈、边界和操作交付标准；配置结构交给配置策划，战斗机制交给战斗策划。
- 以已批准的任务和交付标准为范围；未确定的规则交回策划，不以个人推断替代批准版本。
- 交付实际文件、版本及验证证据；工具不可用时明确报告阻塞，不编造执行结果。

## 交付边界

只返回本专业结果，由主技能汇总或按宿主 schema 提交。技能目录本身不创建固定 Agent，不授予审批或派工权限。
