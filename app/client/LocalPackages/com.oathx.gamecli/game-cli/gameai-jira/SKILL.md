# JIRA 访问

## 当前可用的最小建单入口

- `GameCLI jira --create --summary "任务标题" [--description "任务描述"] [--parent <主任务编号>] --format json`：使用 PM 面板保存的 JIRA Address、Project Key 和 Windows 凭据创建一条任务，不在命令行传递 Token。
- 默认解析项目内的 `Task`／`任务` 非子任务类型；自定义名称可用 `--issue-type <名称或ID>`。`jira --create` 仍是单条最小建单，不提供自定义字段写入。
- 文档驱动的建单通过 [Orchestrator](../gameai-orchestrator/SKILL.md) 执行：先登记需求主任务，策划分析后立即登记对应专业子任务；用户确认具体版本后，项目管理提交计划并复用已有子任务。状态与依赖保存在入口的 `gamecli.workflow.v1` issue property；专业单据携带执行与任务标签，恢复时查询标签并核对已有结果。
- 创建属于外部写入，只在用户已授权创建对应任务时执行。成功读取真实 `key` 和 `url`；失败读取退出码与 `message`。`outcome_unknown: true` 表示可能已创建，必须先到 JIRA 核对，不能自动重试。

## 工作流约束

- 从配置获取站点、项目、字段映射和工作流；文档字段名称不等同于真实字段 ID。
- 写入前读取当前任务、版本、依赖和审批，仅修改本次任务负责的字段。
- 创建、更新和迁移遵守当前任务授权；本技能本身不授权任意外部写入。
- JIRA 保存状态、审批、重试、执行 ID、幂等键和结果引用；大文件存于 Git 或对象存储，回写 URL/Hash。
- 操作前检查执行记录；结果未知或崩溃恢复时核对目标系统已有产物，避免重复创建。
- 先查后写不是并发锁；并发写入使用实际支持的版本检查或串行执行，不能宣称严格 exactly-once。
- 状态通过实际工作流迁移，审批关联批准人及输入/产物版本。
- JIRA 不可用、权限不足或配置缺失时返回 blocked，不用本地 JSON/数据库替代。

返回真实 issue key、字段变更、迁移结果、执行记录引用和错误。超时且结果未知时标记待核对，不直接重复创建。

## 默认主任务与子任务结构

- 每份功能需求登记为一个非子任务类型的需求主任务，保存完整需求和权威流程属性。
- 发现美术、程序开发、测试验收需求时，立即分别在该主任务下创建真实子任务。必须使用项目中 `subtask=true` 的类型，并通过 `fields.parent.key` 关联主任务；标题前缀、描述链接、普通关联不能替代父子关系。
- 主任务必须属于当前项目且不能自身为子任务。项目没有可用子任务类型时停止并说明配置问题，禁止降级创建独立任务。
- `jira --create --parent <主任务编号>` 创建子任务；不带 `--parent` 用于独立主任务。`--issue-type` 指定类型时必须与父子层级匹配。编排器的专业任务自动选择子任务类型，不复用主任务类型配置。
- 父子关系表示归属，任务依赖表示顺序；保留程序与美术、验收与制作任务之间的依赖。当前依赖仍保存在流程属性和描述中，不冒充原生关联关系。
- 恢复时核对子任务类型、父任务编号、项目和稳定标签，全部匹配才复用，禁止重复建单。
- 旧独立任务优先通过官方“转换为子任务”流程转到主任务下，保留单号、内容和历史。不把新建或描述改写当作已完成转换，不因转换受阻自行删除原任务。
