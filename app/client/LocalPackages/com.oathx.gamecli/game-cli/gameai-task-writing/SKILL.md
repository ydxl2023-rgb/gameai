# 任务描述规范

Design 和 PM 输出必须遵守本规范。

- 标题和说明全部使用中文，禁止描述性质的英文。配置表字段、代码标识符、路径、真实编号与链接保留必要原文，结构化字段和角色枚举不翻译。
- 正文只写明确可执行的需求。未决事项放入 `questions`，集中在对话中处理，不进入正文、资源清单和用例，不得自行清空问题绕过审批。
- 隐藏内部快照、恢复标记和执行数据；正式状态由平台服务持久化。
- 使用标题与嵌套列表分层展示需求目标、平台、开发内容、规则、资源、测试和前置依赖，只保留有内容的章节。
- 每个用例按前置条件、操作与处理中、成功结果、失败反馈、异常恢复、测试用例分项换行，不用分号压成一行。不适用项说明原因，不编造分支。
- `acceptance` 的每个数组元素对应一个可验证用例，逐行列出条件、步骤和预期。计划测试标明尚未执行，不能写为通过。
- `depends_on` 引用真实任务或当前计划内稳定临时标识，必须与正文前置关系一致。缺失实际编号不得伪造。
- 需求阅读文件遵守 [HTML 文档规范](../gameai-document-format/SKILL.md)，任务结构化描述不嵌入整页 HTML。
- 遵守 [移动平台规范](../gameai-mobile-requirements/SKILL.md) 和 [依赖与交付规范](../gameai-task-delivery/SKILL.md)。
