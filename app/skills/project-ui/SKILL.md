# 项目 UI 约定

版本：1.1.0

## 风格与资源

- 本项目采用用户指定的原神按钮风格方向：奶油白与深蓝灰配色、细金边、克制装饰；以精美、清晰的最终游戏 UI 效果交付。
- 可见按钮、面板和列表项需要协调的独立图片皮肤，必须调用 Image Gen 制作，不能用纯色白模或仅修改 tint 作为最终效果。背景、图标与控件保持一致。
- 文字保留独立文本控件，不烘焙到按钮底图；透明容器及命中区域保持透明。按需求已有状态交付，不擅自新增交互。
- 可拉伸皮肤标明实测九宫格边距，静态图使用对应导入方式；检查目标尺寸清晰度、边框拉伸与文字对比度。

## 各角色职责

- Design：引用本规范版本，明确窗口、布局和交互；不重复维护另一套风格默认值。
- PM：将规范引用带入白模、美术、最终装配任务；白模不要求最终美术完成。
- Art：按冻结 generationPolicy 生图或核验复用，交付独立资源、状态映射、生图记录与完整效果预览。
- Prefab：白模保持结构与槽位；最终装配引用实际图片，避免旧纯色绑定覆盖皮肤。
- QA：对照任务采用的规范版本验证资源及运行效果，不能把未执行的检查标记通过。

## 版本和冲突

- 本规范只约定项目视觉方向，不改变角色权限、需求审批或验收门槛。
- 已批准需求若限制“只生成 T 图标”“禁止按钮图片”或“所有控件必须纯色”，必须提出需求修订；本文件不追溯覆盖旧批准版本。
- 变更本文件时递增版本。每次执行保存规范正文和 SHA-256；同一次执行重连沿用原快照。需求和任务采用的版本若需改变，应修订并重新审批相关范围。
- 真机验收延期等单次测试决定记录在需求或任务中，不写成所有项目的永久豁免。

## 本项目平台与交互默认值

以下约定从原通用技能迁入，保持当前项目选择；只用于新需求编写，已批准版本以冻结契约为准，不能追溯改写。用户明确修改时采用其新要求并走修订流程。

- 当前工程严格限定移动平台，所有功能和资源以触屏操作为前提，无需再次询问是否面向电脑。
- 禁止设计或输出右键菜单、鼠标操作、键盘快捷键、悬停等桌面交互。不能把桌面方案作为建议或备选写入单据。
- 使用点击、触屏拖动等移动交互。额外手势或功能入口只有在明确需求支持时才作为确定规则；缺失时在对话询问，不编造已批准方案。
- 背包拖动描述为触屏拖动；丢弃可采用触屏按钮方案，但按钮位置、丢弃数量及确认方式不能因平台约束而自动视为已批准。
- 美术需适配触屏可点击区域、移动端界面可读性和拖动反馈；未给定屏幕尺寸或资源规格时，不擅自写死数值。
- 测试操作必须能在移动端完成。该技能只约定平台约束，单据排版由调用角色另外加载对应技能。

## 默认领奖成功交互

移动端领取成功后直接弹出奖励窗口：顶部显示“领取成功”，中部为实际发放的道具列表（图标、名称、数量），底部小字“点击任意地方退出”。不设置确定按钮。点击奖励层任意位置关闭该层并返回原界面，关闭点击不得穿透触发下层控件。仅收到成功结果或查询确认已发放后展示；明确失败或结果未知时展示对应提示，不伪造成功。重复展示或关闭不再次发奖。线框、控件说明和验收必须一致；这是默认交互，用户对具体功能明确另作规定时以其规定为准。

## 默认明确失败反馈

明确业务失败时只显示失败原因提示条，不打开可操作的失败弹窗。提示条为横向长条，从屏幕中间出现，向上飘动一段后消失；不带确认、关闭或重试按钮，不可点击，不阻塞正常界面操作。原界面根据服务器结果同步状态。不要擅自规定未经设计的固定时长和位移像素。

操作交付标准必须写明该触发、显示、上浮及消失过程；第四节动画需求必须列出提示条的位移和消失表现，不能同时声称本期完全无动画。测试覆盖失败原因正确、无按钮、上浮消失及不阻塞交互。

网络异常、断线、超时与业务失败统一使用上述原因提示条，不设置独立网络异常描述区、弹窗或重试按钮，不增加专门的用户操作。网络恢复后由系统自动查询权威状态；用户再次进入原业务界面时也同步查询。

表现统一不等于业务结果相同：响应丢失仍属于结果未确认，提示使用“网络异常，领取结果确认中”等准确文案，不声称领取已失败。核对已发放则恢复原成功结果；确认未发放且有效才恢复原领取入口；到期按结算规则处理。核对失败时不得自动重复提交发奖请求。普通业务按钮不承担未经核对的重复发奖。操作说明、线框和测试不得残留独立网络异常或重试控件。

## 手机底框与设计画布

本项目后续手机线框统一使用1920×1080横屏设计画布，以带刘海的 iPhone 外观作为设备背景：左侧刘海、圆角屏幕、底部手势条，标示布局安全区域。所有界面在同一比例的屏幕内部展示，继续单列按操作逻辑排序。

该尺寸是用户指定的设计画布，不宣称它是某款手机的原生分辨率。安全区域仅作示意，运行时按设备实际安全区适配。文字、按钮及关键内容避开刘海和手势区域，不裁剪或遗漏控件。设备底框和辅助标记不属于实际游戏美术交付。

优先使用内嵌 SVG 的 viewBox 保持画布比例、清晰缩放与离线打印；标注画布尺寸。不得拉伸屏幕、改变比例或把多台手机并排排列。单个屏幕内的奖励卡等可按实际横屏布局排列。

绘图时使用随技能分发的 [横屏手机底框](../../../game-cli/skills/common/gameai-document-format/assets/phone-landscape-frame.svg)，在内部1920×1080画布中替换示例内容。


## 本项目奖励配置格式

用户已确认奖励元组固定为两项：`ItemId`、`Number`，均为 `int`。固定配置类型为 `List<(int:ItemId,int:Number)>`，C# 类型为 `List<(int ItemId, int Number)>`。标准填表示例 `{{40,8},{10,6}}` 表示道具40发8个、道具10发6个；单项也使用 `{{40,8}}`。不允许第三项或自行引入奖励类型。奖励字典的道具主键也必须是 `int`，数量为正整数。每档一行，一个 `Rewards` 列表保存本次全部奖励，列表顺序作为展示顺序。
