1 设计目标

用一个固定输出、自动退出的 Windows C# 控制台程序，验证需求审批、开发发布、实际产物测试和人工最终验收的最小完整闭环。程序的可见结果为标准输出一行 Hello World!。

本需求属于工具测试。平台按用户明确选择采用 Windows 控制台，交互不涉及移动触屏。只创建独立示例工程及必要交付证据，不引入额外集成项目。

本版本状态为“待人工审批”。本文全部开发要求、发布要求和验收用例均尚未执行。线框中的输出是预期示意，不是运行证据。当前只交付需求，不生成程序、不创建任务、不声明测试通过。

2 功能综述

2.1 固定行为与范围

  • 独立工程位于仓库根目录相对路径 app/samples/HelloWorld/，目标框架为 net8.0。
  • 使用本机已安装的 .NET SDK 9.0.314；不安装 SDK、额外第三方 NuGet 包或系统服务。
  • 运行入口为发布目录中的 Artifacts/hello-world/publish/HelloWorld.exe。
  • 标准输出恰好一行 Hello World!，大小写、单词间一个空格和感叹号固定，无逗号、前后空格或额外空行；允许 Windows 换行。
  • 标准错误为空，进程退出码为 0，从进程启动到退出不超过 5 秒。
  • 程序自行结束，不等待键盘输入，不联网、不读取配置、不创建状态数据。
  • QA 连续独立启动发布产物两次；每次都必须完整满足相同标准。
  • 不放入 Unity Assets，不调用 Unity，不更改 GameCLI 或 GameCLIServer 业务代码，不使用其他工程，不增加测试框架。
  • 不增加登录、奖励、配置功能或美术任务。

3.5 异常处理与返修

情形判定与下一步恢复要求
编译或发布失败开发保留日志并定位原因；未交付有效发布产物前，不进入成功验收。环境问题据实阻塞；确认代码问题后由原 Developer 修复并重新发布。
缺少运行时等环境问题记录真实错误、命令和环境信息，标记环境阻塞，不伪造业务缺陷或通过结论。环境恢复后由原 QA 验证同一计划中的有效交付；不擅自安装或改造系统。
确定的代码缺陷回到原 Developer 返修，复用原任务与依赖关系。重新提交发布文件、日志及列表；原 QA 更新哈希并重新执行完整两次启动及受影响用例。
测试中断或采集失败记录本次测试未完成，不把缺失证据当作标准错误为空或退出成功。恢复采集后重新完整执行；保留原记录以供追溯。

本程序无网络请求和状态写入，不需要业务重试、补偿、同步或关闭动画。进程自行退出即完成本地运行；异常恢复由开发及 QA 流程处理。
