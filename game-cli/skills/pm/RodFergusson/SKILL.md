- 当前 UI 制作范围必须读取 [UI 规划](ui/SKILL.md) 与 [美术规划](art/SKILL.md)。由同一次执行结合两模块输出统一计划，不分别创建重复任务。

## 当前粒度与依赖

当前 UI 制作范围内，每个明确独立窗口固定且仅有三项：Prefab 白模 → Art 窗口图片资源包 → Prefab 最终装配。装配依赖白模与资源包；普通控件、背景、按钮、状态、滚动容器和列表项均包含在窗口内，本轮不另拆组件。不得为了满足数量虚构需求；无 UI 时说明不适用。仅拆批准范围，不拆服务端工作。

白模交付完整层级、布局、尺寸、控件属性与资源槽位。Art 根据白模生成图片，给出切片/九宫格/透明与槽位映射及预览。Prefab 完成替换和装配，不把美术资源生成职责交给 Prefab。每项明确前置、操作、成功、失败、恢复和检查方法，不以拆分计划冒充实际验收。

## 窗口级任务粒度（用户已确认，硬性规范）

本节是当前 UI 制作流程的粒度基准，优先于其他引用技能中按组件或细功能分别建单的通用描述。完整独立窗口是交付单位；复杂度通过任务内交付清单表达，不通过增加子任务表达。

| 每窗口固定任务 | 执行角色 | 完整交付范围 | 前置依赖 |
| --- | --- | --- | --- |
| 窗口白模 | Prefab | 完整预制层级、布局、控件属性、内部状态和资源槽位 | 已批准需求 |
| 窗口美术资源 | Art | 按白模统一交付该窗口所需图片、状态样式与资源映射；无新增图片时核对复用资源 | 本窗口白模 |
| 窗口最终装配 | Prefab | 替换资源、绑定引用、完成已约定的 UI 表现并检查层级、显示状态、输入和适配 | 本窗口白模及美术资源 |

- 不单独拆背景、ICON、版本号、按钮、下拉容器、滚动列表、列表项、状态或单张图片。它们作为对应窗口任务内的交付与验收检查项。
- 同一窗口的多张线框、子章节、内部浮层和不同状态不增加任务；是否独立窗口以需求清单明确边界为准。
- 一个窗口三个子任务，两个窗口六个子任务；主任务和团队分类节点不计入制作子任务。不能额外增加检查、资源整理或重复装配任务。
- 无新增图片也保留 Art 阶段，交付资源复用核对及槽位映射，不虚构生图。共享资源只生产一次，在使用窗口中引用，并沿用清单已明确的跨窗依赖。
- 三阶段沿用相同最终预制名称与英文节点命名；每项保留该窗口的完整原始 HTML、线框、结构和属性，说明及验收按阶段区分，不能复制成三个相同任务说明。
- 当前不生成程序业务、服务端或 QA 子任务。范围变化须先修订批准需求并同步骨架规则，PM 不自行例外细拆。

当前登录需求的固定预演基准：`UILogin.prefab` 与 `UIReasonToast.prefab` 各三项，共六项。登录下拉列表、处理中和成功占位状态归登录窗口内部；提示背景与原因文字归提示窗口内部。该例只用于核对本需求，不强加给其他需求的窗口边界。

## 只读拆分预演

用户只要求查看拆分结果时，对话宿主可直接读取本技能及 UI/Art 模块，按当前需求清单列出“任务、执行角色、交付内容、前置依赖”。明确这是技能预演，不声称启动过 PM Agent，不上传、不建单、不派发。预演认可只确认拆分方式，不替代 Track 对正式需求版本的人工审批。

## 原始 HTML 与发布校验

每张 Prefab 任务 source_refs 首项定位真实窗口 section 锚点；窗口说明、线框、层级树、属性表完整保留在同一任务，不能按子章节拆任务。宿主截取完整原文、样式和 SVG 定义，生成独立 HTML 并绑定批准版本和哈希；缺少精确来源应报告缺口，不能展示无关窗口或仅摘要。

返回宿主 schema，任务临时编号唯一、依赖真实且无循环，覆盖批准窗口但不重复拆分。宿主复核审批、版本与依赖后原子建单。只读拆分不授予后续制作权限，保持原有手动派发及自动授权。


## 按交付清单准确拆分（硬性要求）

先读取文档格式技能“UI 交付清单契约”及 HTML 中 ui-delivery-manifest，对照可见窗口清单逐项核对，不通过语义猜测替代明确的 independent、parent_window、anchor。清单缺失、JSON无效、边界未决、版本不符、编号/锚点/映射冲突时停止计划交付，使用宿主允许的错误或缺口通道报告；无阻塞字段时不得用成功计划伪装缺口，不改写批准文档。

当前只为 independent=true 的窗口生成任务，保留 deliveries.id 作为临时任务编号，逐项对应 whitebox/Prefab、art/Art、assembly/Prefab；内部区域不建单。任务数量必须为独立窗口数×3，不新增程序、QA或零散控件任务。每个编号恰好覆盖一个窗口阶段，depends_on逐项沿用清单，source_refs首项使用该窗口真实anchor。每张任务仍带完整窗口原文、线框、结构和属性；美术范围只取generate=true且owner_window属于该窗口的资源，既有及共享资源作为引用依赖。

输出前给出逐窗口交付覆盖核对，检查遗漏、重复、未声明任务、资源重复生产、悬空/循环依赖；零新增图片阶段不能虚构图片生产，明确既有资源核对与映射交付。需要例外时退回文档修订与审批，不能自行压缩、扩展任务范围。服务端已实现 v1/v2 清单结构校验和固定骨架核验；可见正文与清单的语义一致性仍由 Design 与 PM 审查，不能把结构通过声称为全文语义证明。

## 固定骨架补全（第一阶段）

云端提供 skeleton 后，仅补充 summary 与每项 title、description、acceptance。原样保留 id、role、source_refs、depends_on，阶段由稳定 ID 后缀定义；不输出 window_id、phase 等宿主 schema 以外字段。每项 source_refs 必须恰为所属完整窗口的 #section 锚点，不另加文本引用。不得新增、减少或更换任务结构；可见正文与清单不一致时报告阻塞，退回文档修订审批。

跨窗口共用图片由唯一 owner_window 的 Art 任务生产，使用方 assembly 除本窗口两项前置外还依赖 owner_window-ART；这些边必须已明确写入批准清单。所有图片控件都要映射唯一资源（静态图 static 或九宫格 sliced），generate=false 表示核对和复用既有资源，不能虚构生图。

## 英文资产命名（强制）

遵守 [文档规范](../../common/gameai-document-format/SKILL.md) 的“UI 预制与节点英文命名”。最终窗口资产必须为 `UI<功能英文>.prefab`；根节点使用同名无扩展名，子节点用标准英文 PascalCase。登录为 `UILogin.prefab`，子节点如 `LoginBackground`、`TestIcon`、`Version`。文档树与线框展示真实英文名称，不显示 S0/L01 等编号前缀。稳定 id 仅作内部关联；绘制顺序单列。新清单 v2 必须带 prefab_name 与 controls.name，后续原样继承，不以编号命名节点。
