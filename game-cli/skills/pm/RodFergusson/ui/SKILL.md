# PMUI

## 单一职责

以已批准窗口清单及 ui-delivery-manifest 为唯一交付边界。每个独立窗口一项白模、一项最终装配，美术模块提供中间资源包；普通控件和列表项均归窗口内部，不凭复用价值额外拆单。完整保留层级、绘制顺序、尺寸、控件属性和资源槽位，source_refs定位整个窗口section。清单缺失或与线框矛盾时阻塞，不能猜测。遵守总入口的窗口×三阶段覆盖规则。

## 输入与输出契约

读取宿主指定的批准版本、全局规则、负责章节完整 HTML、共享组件及跨专业契约，核对版本与 SHA-256。不得仅凭摘要或线框截图拆任务。缺少明确结论时报告缺口，不自行扩大需求或重新批准。

每项草案包含稳定临时编号、来源章节/锚点、所属独立窗口、范围、不含范围、交付文件、前置依赖与交付验收标准。验收覆盖前置条件、操作处理、成功结果、失败提示、异常恢复和测试用例。需要阅读的任务单据使用独立 HTML，完整保留相关原文、样式、线框和控件层级，不用摘要代替。

跨专业依赖使用来源锚点和交付契约标识，由总 PM 合并解析为真实任务编号；不能猜测平台编号。按宿主 schema 返回草案与缺口；无 schema 时采用公共结果结构。由 RodFergusson 在同一次执行中汇总，不直接发布、审批、启动制作或改变权限。

遵守 [公共契约](../../../common/SKILL.md)、[单据规范](../../../common/gameai-task-writing/SKILL.md)、[交付规范](../../../common/gameai-task-delivery/SKILL.md)、[HTML 规范](../../../common/gameai-document-format/SKILL.md)。只使用自己的成员技能目录，这是 RodFergusson 的内部规划模块，不是独立 Agent，不调度其他 PM。

本模块仅定义 PM 拆分规则，不执行制作。当前 UI 调试按独立窗口交付，不额外拆列表项或单个控件；美术按窗口资源包交付。

服务端固定骨架优先：本模块仅用于补充内容，不再决定任务数量、编号、角色或依赖。严格按 RodFergusson 主技能“固定骨架补全”执行；发现矛盾返回阻塞，不自行修订已批准清单。

粒度与只读预演统一遵守 [主技能](../SKILL.md) 的“窗口级任务粒度”。每窗口仅补全白模和最终装配两项，列表项模板、内部状态与 UI 表现均写入对应任务的检查项，不增加第三项 Prefab 任务。
