# 任务依赖与交付

平台是审批、依赖、执行及交付状态的权威来源。Agent 只生产本阶段文件与证据，不自行建单、审批、修改状态或启动下游。

## 启动与输入

- 初稿讨论不建任务。正式需求经 Track 人工审批后，PM 审查，服务端校验并事务性建单；实际执行还须满足角色授权、依赖与租约。
- 使用宿主提供的 platform_context、批准版本、冻结生产输入和上游交付。宿主负责数据库核验、续约和状态回写；模型不读凭据或猜服务端口重复核验。输入缺失或租约失效时报告具体原因。
- 父子归属不代替执行依赖；依赖的文件及版本必须与宿主核验结果一致。发现文件变化或上游失效，报告宿主重新核验，不能自行放行。
- UI 三阶段职责、资源策略与等待分类统一读取 [UI 公共交付契约](../gameai-ui-delivery-contract/SKILL.md)。程序和 QA 只有在实际任务范围中才执行，不额外加入当前 UI-only 骨架。

## 文件和证据

- 白模交付结构、原生组件、绑定及允许延后的槽位；Art 交付冻结槽位、动画与特效资产和映射；最终装配消费这些资产完成绑定及本阶段验证。
- Development 按任务实现业务并提供实际构建与功能证据；QA 核验指定版本。业务开发可以依赖稳定白模绑定，最终联调依赖正式装配，不要求所有开发一律先等美术。
- 专业 execute 严格使用宿主 schema。files 列出真实交付文件与检查证据，checks 只包含本阶段必检项；未执行不得写通过。报告、图片、日志不能代替实际资源或代码。
- 交付文件统一记录实际路径、版本及 SHA-256。结果由服务端验证并保存；是否完成或待验收取决于当前流程策略，Agent 不承诺自动放行。

## 失败与恢复

报告失败位置、工具结果和已有产物，保留证据。技术修复、结果重传、未知进程核实及外部等待由编排器分别处理；不在 Agent 内重建任务或无限重跑。人工审批与版本变更不能靠重试绕过。

任务描述遵守 [任务说明](../gameai-task-writing/SKILL.md)。
