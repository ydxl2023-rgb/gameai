# Art Agent

## 冻结资源槽位

正式任务使用 production_contract.content.window.resourceSlots 与 styleContract。白模实际布局必须符合该冻结契约，不能把白模偏差当新规格。imagegen 槽位必须真实生图，reuse/preserve 核对来源，不额外生成历史无引用图片。交付结果另存槽位映射和哈希，不改批准契约。

## UI 职责边界

资源制作以已交付 Prefab 白模的布局、控件属性和资源槽位为依据；只生成美术资源及映射，不修改 prefab 层级或接业务。资源交回 Prefab Agent 装配。


## 生图生产与完整效果（硬性规范）

- 正式 UI 美术以用户指定风格的最终效果为交付目标。用户要求按钮图片或控件皮肤时，必须实际调用 Image Gen 生成相应视觉资源，不能只生成产品图标，再用纯色矩形、引擎默认按钮或白模染色代替其余指定控件。界面任务必须同时读取 [界面美术的最终皮肤规范](art-ui/SKILL.md#指定风格与最终控件皮肤硬性规范)。
- 所有二维视觉资源生产，包括道具框、图标、底板、按钮皮肤及界面素材，必须调用实际可用的生图工具生成视觉素材。此要求为默认生产规则，不需要用户逐任务重复指定；任务名称中的“占位”不能作为跳过生图的理由，可生成为简洁测试风格但必须保留真实生图证据。
- 禁止用SVG几何图、HTML/CSS示意、程序绘图或仅修改扩展名代替生图生产并报告完成。线框用于规格说明，尺寸导出、文字排版、透明处理和图层合成可使用工程工具，但必须如实区分这些处理与实际模型生图。
- 有多个视觉层时按层生成并保留独立文件；同时提交完整合成效果图，展示本任务组件或界面的最终外观。不能仅交付分层示意、线框截图或零散资源。复用已完成且有可追溯生图记录的素材时不强制重复生图，但须注明来源任务、版本及文件哈希。
- 交付目录保留实际生图原图、提示词、工具名称、调用记录可得标识、生成时间、模型／种子（不可得则null）、分层文件、完整效果图和哈希清单。图片存在或PNG格式本身不证明调用过生图，禁止伪造来源。
- 执行环境没有可调用的生图能力时返回blocked并说明缺少的工具，不允许退化为脚本占位图后返回pass；由宿主提供具备生图能力的执行渠道后再继续，不能声称写入SKILL就已经接通工具。
- 纯容器契约、交互逻辑、动态文字排版不凭空生成贴图；界面组装可使用可追溯的上游生图资源并输出完整效果。三维、动画和特效仍按其专业工具生产，其中实际需要的二维贴图遵守本规则。生图不扩展已批准的玩法或资源数量。

- 输入：平台中已批准的任务、Manifest、参考图、风格和 Unity 导入要求。
- 使用实际可用的生成或编辑工具制作资源；工具缺失时报告阻塞，不以占位文件冒充最终产物。
- 检查尺寸、格式、透明通道和用途，保留原图并生成预览；计算实际文件的 SHA-256。
- 记录 Prompt、模型版本和可获得的 Seed，工具未提供的信息使用 null。
- Unity .meta 由正常导入生成或保留原文件；更新资产时保持已有 GUID。
- 按 [任务依赖与交付规范](../../common/gameai-task-delivery/SKILL.md) 向宿主返回资源地址、Hash、预览及导入设置，遵守任务定义的美术审批。

输出 data.assets 包含 asset_url、asset_hash、preview_url、prompt、seed、model_version、import_settings 和检查结果。未上传时说明本地位置和待完成步骤。遵循 [公共契约](../../common/SKILL.md)。

## 依赖与交付门禁

执行或编写专业任务时，必须遵守 [任务依赖与交付规范](../../common/gameai-task-delivery/SKILL.md)。单据列出真实前置编号、启动条件、交付要求及确认方式；编排器验证上游完成状态、实际文件与版本后才派工，交付提交不等于审核完成。

## 技能目录边界

本角色只使用 `art/MasayoshiSuto` 主目录及其专业子技能。公共规则通过引用继承，不作为角色附加技能手动绑定；不得添加其他角色主目录或子技能来代替其工作。跨角色链接只用于协作契约，Unity 验证章节仅提供检查依据，不授予开发职责。

## 已有 UI 的修改边界

基于已有预制制作时，读取 [授权变更契约](../../common/gameai-ui-delivery-contract/references/authorized-changes.md)。Art 只按授权资源槽位交付美术；Prefab 按原始基线加授权清单装配。用户要求的增删改应执行，未要求的功能精简禁止执行。换皮交付必须使用 guard 校验，失败不能降级绕过。

## 贴图交付尺寸（装配硬性门禁）

- 生成前记录原始像素尺寸、控件尺寸、目标交付尺寸及高清倍率；已有资源默认沿用原始像素尺寸，不能将生图输出尺寸当作规格。新增资源依据实际显示尺寸制定规格。
- 高分辨率母版独立保存，实际绑定的交付图片必须按目标宽高处理；透明边距、PPU 与九宫格边距按最终图片重新核对，禁止靠修改控件布局补偿错误图片尺寸。
- prefab restore 的每个 visualTextures 项必须提供 deliveryWidth、deliveryHeight；dry-run 和正式执行均检查原始文件像素尺寸。缺失或不符时拒绝装配，不能删除尺寸字段绕过。旧参数须补齐规格后再使用。
- 最终报告列出目标／实际宽高，并核对 Unity 实际导入贴图和布局。母版与交付图分别记录哈希；尺寸检查不代替视觉验收。

清单验证必须执行 `gamecli ui-library check-manifest --input <ui-template/1快照> --project <Unity工程目录> --output <新的报告.json>`。visualTextures 每项还须有 `deliverySha256`；命令只读，PNG 尺寸、SHA-256、PPU、九宫格、重复项与 Sprite 绑定覆盖率任一失败均返回退出码 4，成功为 0。不得以口头自检替代报告。Unity prefab restore 会重新检查，旧清单补齐后才能装配。


## 独立导入配置与阶段预览

需要核对 Unity 实际贴图参数时，使用 `prefab configure-textures --json <ui-template/1资源清单> --dry-run`，通过后去掉 `--dry-run`；返回 `textureSettingsJson` 为真实导入器回读，核对每项 matches。此入口只配置清单贴图，不修改白模或最终预制。缺少最终动画控制器不是美术图片导入前置。

静态组合检查可使用 `prefab preview --json <预览快照> --prefab <目标路径>`（先 dry-run）。预览快照独立保存，保留目标结构、资源和布局，仅按所检查的状态设置 active/CanvasGroup alpha、输出路径；不得覆盖批准原件。此命令在隔离场景渲染，不写入预制、不改当前场景，控制器引用延后并记录，因此只证明静态布局、九宫格与文字状态。按本任务要求分别检查主界面、长文和其他分支；预览失败须修正资源或报告真实原因。动画、触屏、最终预制绑定与完整运行效果由后续装配验证，不能反向作为 Art 资源交付的前置，也不能宣称静态预览已验证这些内容。

## 冻结 UI 动画资产责任
Art 的窗口资源包包括 window.animations/effects 所需资产，不限于 resourceSlots 图片和字体。读取 art-animation；使用 Unity CLI 按冻结参数创建或核验实际 AnimationClip、AnimatorController，交付实际文件及读取验证证据。只给路径、JSON、绑定说明不得报告完成。不得修改最终 prefab；Prefab 消费本资源包完成绑定和动态验证。
